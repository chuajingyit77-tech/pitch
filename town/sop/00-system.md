# 系统运作 SOP

一份作品从交进来到评完，每一步谁做什么。这份是给人看的；66 位检查员各自的 SOP 在 [`town/agents/`](../agents/README.md)。

---

## 角色

| 角色 | 是谁 | 要做什么 | 需要什么账号 |
| --- | --- | --- | --- |
| 提交人 | 公司任何同事 | 填表单、上传文件 | 公司 Google 账号（本来就有） |
| 系统 | 这套程序 | 分类、改名、归档、评审、写报告 | 不需要 |
| 检查员 | 66 位，各管一件事 | 每位给一条结论 | 规则层 11 位不用模型 |
| 复核人 | 你（或项目负责人） | 看报告、定状态、回同事 | Claude 或任何模型（可选） |

**只有复核人需要 AI 账号。** 这是走 Google 这条路最大的好处 — 同事零门槛。

---

## 一份作品的一生

### 第 1 步 · 交件（同事做）

三种方式，任选：

1. **Google 表单**（推荐）— 填项目、类型、一句话说明，上传文件。附件自动进 Drive
2. **直接丢进收件夹** — 文件名照这个格式：`项目__类型__提交人__一句话说明.pdf`
3. **丢进对应子夹** — `_收件/门店扩张/设计/招牌稿.png`

三种都不用登录这个系统，也不用装任何东西。

### 第 2 步 · 判断这是什么（系统做，自动）

系统按这个顺序找资料，前面的赢：

1. 文件旁边的 `<文件名>.town.json`
2. 表单回应 CSV 里的那一行（`--manifest`）
3. 它被丢进的子夹：`_收件/<项目>/<类型>/`
4. 文件名约定：`项目__类型__提交人__说明`
5. 文件自己的内容（看关键词猜类型）

**任何一项是猜的，报告开头都会写出来。** 比如「自动判断：类型（看内容猜的）、提交人（文件里看不出来）」。看到这行就知道该补什么资料。

### 第 3 步 · 归档（系统做，自动）

文件被**复制**（不是搬走）到：

```
<档案库>/<项目>/<类型>/<日期>_<提交人>_<说明>.<原扩展名>
```

例如：`12_作品提交与评审/档案库/门店扩张/提案/2026-11-06_张三_第一版方向确认.pdf`

原件留在收件夹不动。要搬走必须明确跑 `--move`。

### 第 4 步 · 读（系统做，自动）

- PDF（含中文）、Word、PPT、Excel、纯文本 → 抽出文字
- 图片 → 图本身送给模型看
- `.psd/.ai/.fig` → 归档但不评审，报告里写明「请另交一份导出版」
- 扫描版 PDF → 报告里写明「这是图片版，要先 OCR」

**读不出来就说读不出来，绝不评审空内容。**

### 第 5 步 · 评审（系统 + 模型）

按文件类型挑出该看的检查员：

| 类型 | 会叫到几位 |
| --- | --- |
| 提案 | 63 |
| 报告 | 40 |
| 合同 | 37 |
| 设计 | 15 |
| 文案 | 13 |
| 其他 | 11 |

每位给一条：`pass` 通过 / `flag` 留意 / `fail` 不过 / `skip` 这份里没有我能判断的东西。

跑的顺序是先规则层（免费、瞬间、结果固定），再模型层。**没接模型也会出报告** — 规则层那 14 条照跑。

### 第 6 步 · 写报告（系统做，自动）

报告落在作品旁边：

```
<档案库>/<项目>/<类型>/_评审/<同名>.评审.md
```

报告的结构固定：

1. 头部 — 读不出内容的说明、系统猜了哪些
2. **必须处理** — 所有 `fail`，带原文引用和「要做的」
3. **值得留意** — 所有 `flag`
4. **全部结果** — 一张表，66 位各一行
5. **没跑成的** — 哪几项没跑、为什么

Markdown 格式，Drive 和手机上都能直接看。

### 第 7 步 · 更新清单（系统做，自动）

`<档案库>/清单.csv` — 每一份作品一行：日期、项目、类型、提交人、文件路径、状态、不过几项、留意几项、说明、报告路径。

带 BOM，Excel 和 Google Sheets 打开中文不乱码。**即使这个程序以后不用了，硬盘上那份档案库仍然是完整可读的。**

### 第 8 步 · 复核（你做）

打开报告，看「必须处理」那一段。然后：

- 没问题 → 回同事，可以往下走
- 要改 → 把「必须处理」整段贴给同事，里面已经写好了每一项要做什么
- 系统猜错了 → 改文件名或补 `.town.json`，然后 `--force` 重跑那一份

## 日常怎么跑

### 手动

```bash
node town/bin/town.js run
```

已经处理过的会自动跳过（按 路径+大小+修改时间 记账）。同事改了文件再交，记账键会变，会重新评审。

### 定时（推荐）

macOS / Linux，每小时一次：

```cron
0 * * * * cd /path/to/pitch && TOWN_PRESET=deepseek TOWN_API_KEY=sk-... node town/bin/town.js run >> /tmp/town.log 2>&1
```

Windows 用「工作排程器」，每小时执行同一条命令。

机器开着、Drive 桌面版在同步，这件事就一直在跑。

## 出状况怎么办

| 情况 | 怎么处理 |
| --- | --- |
| 报告说「没有接模型」 | 设 `TOWN_PRESET` 和 `TOWN_API_KEY` 后 `--force` 重跑 |
| 报告说「这是扫描件」 | 用 Drive 的「用 Google 文档打开」做 OCR，或请同事交文字版 |
| 项目/类型判断错了 | 改文件名成 `项目__类型__提交人__说明`，或写一个 `.town.json`，然后 `--force` |
| 某一位检查员老是误报 | 改 `town/core/agents.data.js` 里他的 `criteria`，跑 `sops` 重新生成，再跑测试 |
| 评语太空泛 | 多半是模型太小。先看报告里 `fail` 那几项 — 规则层的结论跟模型无关，一定可信 |
| 收件夹文件太多跑太久 | `--limit 20` 分批跑 |
| 想换模型 | 换一个环境变量。系统不动 |

## 不要做的事

- **不要把这个档案库当唯一存放地。** 它是收件和评审的地方；Drive 同步到硬盘和你们原本的归档流程才是长期归档
- **不要直接改 `town/agents/` 里的 SOP 文件** — 它们是生成的，改 `agents.data.js` 才算改
- **不要把模型层的结论当定论。** 规则层的结论是确定的；模型层的要人看过。报告最后一行就写着这句话
- **不要在收件夹里放密码、身份证、银行资料。** 这套系统是给「交作品」用的，不是机密档案库

## 要改什么，改哪里

| 要改 | 改这个文件 |
| --- | --- |
| 某位检查员查什么、怎么查、判定标准 | `town/core/agents.data.js`（改完跑 `sops`） |
| 加一条免费的规则检查 | `town/core/rules.js` 加一个函数，在 roster 里指向它 |
| 加一个模型供应商 | `town/core/llm.js` 的 `PRESETS` |
| 提示词的整体框架（换便宜模型时调这里） | `town/core/review.js` 的 `systemPrompt` / `userPrompt` |
| 报告长什么样 | `town/core/review.js` 的 `reportMarkdown` |
| 文件夹结构、命名规则 | `town/core/classify.js` 和 `town/core/drive.js` |
| 文件夹位置、模型、并发 | `town/config/town.config.json` |

改完一定跑 `node --test`。测试里有 55 项是专门针对这套系统的，包括「两位检查员不能查重复的东西」和「文件名不能写到档案库外面去」。
