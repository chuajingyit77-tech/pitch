# 漏掉的问题

这里记两类事：agent 说“做完了”之后才被发现的问题，以及交付前靠验证抓到、但差一点漏出去的问题。目的只有一个：同样的问题不漏第二次。

## 怎么记

每条写五件事：日期；漏了什么；怎么发现的；当时哪些检查是通过的；应该由什么检查抓到。

## 什么时候变成规则

- **同一类问题出现两次**，并且能从改动的文件或内容里认出来，才提议加规则：加一条到 `checklist.md`，或者加一句到 `REVIEW.md`。只出现一次的先记着，不加。
- 加之前先让人或另一个 agent 找反例：这条规则会不会误伤正常的改动。
- 规则的修改单独提交，由主人批准。

## 不稳定的测试

时过时不过的测试，不许跳过、不许加 sleep、不许重跑到过为止。先找根因；找不到就删掉这个测试，并在这里写明原因。

## 定期修剪

规则只增不减，最后没人看。每个季度，或者清单超过 20 条时，过一遍：从没触发过、从没抓到过问题的条目删掉；重复的合并。

## 记录

### 1 · 2026-11-18 · 失败的测试在界面上显示成绿点（交付前抓到）
- 漏了什么：编程 agent 跑测试失败时，工具卡片仍是代表成功的绿点。连续三次失败看上去是三次成功，紧接着却提示“连续 3 轮没有通过”。
- 怎么发现的：把真实服务启动起来，在浏览器里走了一遍“三轮不过”的任务，看截图时发现。
- 当时通过的检查：40 项自动测试全过。它们检查的是数据，没有一项看过屏幕。
- 应该由什么抓到：实际运行一遍。已补上：检查失败的卡片显示红点和“检查未通过”，并有测试 `each check is marked pass, fail or unclear for the screen, so a failed test run cannot look like a success`；清单加了 R12。
- 同类问题第几次出现：第 1 次。

### 2 · 2026-11-18 · 配方里的测试命令在这台机器的 Node 版本上跑不起来（交付前抓到）
- 漏了什么：验收配方里写的是 `node --test verification/test/`。Node 22 不接受把目录当参数，这条命令一运行就报错。
- 怎么发现的：照着配方把命令实际运行了一遍。
- 当时通过的检查：语法检查通过；脚本本身的测试还没写完。
- 应该由什么抓到：实际运行一遍。已改成 `node --test verification/test/*.test.mjs`，现在 `verify.mjs` 每次都会真的执行这条命令。
- 同类问题第几次出现：第 1 次。和第 1 条的共同点是“看着对，一跑才知道不对”。
