# Agent Hub

一个系统，四个 AI agent，在你自己的电脑上运行。

| Agent | 做什么 | 默认用哪家模型 |
|---|---|---|
| 通用助理 | 查资料、读写文件、记住你的偏好，并把专业任务委派给其他 agent | Kimi |
| Pitch 生成 | 调研 → 设计叙事 → 生成可直接分享的网页版 pitch，自动核对每个数字的来源 | Claude |
| 销售获客 | 找潜在客户、带来源打分、起草外联邮件，全部进审批队列等你批准 | Grok |
| 编程 | 在你的代码仓库里读代码、修改、跑测试；改文件和运行命令前先问你 | OpenAI |

只配一家的 key 也能用：没配置的厂商会自动改用已配置的那家。

## 开始使用

需要 Node.js 20 或更高版本。

```bash
cd agent-hub
npm install
npm start
```

打开 http://localhost:4317 ，点左下角 **设置**：

1. 给任意一家厂商粘贴 API key，点 **获取列表** 选一个模型，保存。
2. 想用编程 agent，再填上你的代码仓库路径。

没有 key 也想先看看界面：`npm run demo`，会用一个模拟模型走完每个 agent 的流程。

## 它是怎么保证安全的

- **只在本机**：服务只监听 127.0.0.1，并拒绝来自其他网站的请求。key 只保存在 `data/config.json`。
- **改动要你同意**：编程 agent 改文件、运行命令前都会弹出确认。删除目录、强制推送、重置历史这类命令每次都要确认，“本次对话都允许”对它们不生效。
- **文件不出工作目录**：所有文件操作被限制在工作目录内，符号链接也绕不出去。
- **不会自动发邮件**：销售 agent 只能起草。你批准后，用“在邮件客户端打开”或导出 CSV 自己发出。“不再联系”名单上的公司会被拒绝保存和起草。
- **不编造数字**：pitch 里出现的每个数字都要在事实表里有来源，否则那一页会被标上“待确认”。
- **网页内容只是资料**：agent 被要求不执行网页、文件里夹带的指令；生成的文件在沙箱里显示，无法访问本系统的接口。

## 验收：说“做完了”要拿出证据

做法来自 Anthropic 2026-11-16 的文章 [How the Claude Code team thinks about verification](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/)：agent 写得快，人不可能逐行看，所以让 agent 自己把证据交出来，人只看证据。

- **每次任务都盖章**：回答下面会标出这次是怎么验证的：已验证、未验证、检查未通过、验证已过期（检查通过后又改了文件），或者已停下等你决定。委派给别的 agent 的任务，章会跟着结果一起传回来。
- **只认可信的证据**：测试、lint、类型检查、构建这类命令才算检查，而且要看得到它自己的退出码。`npm test | tail`、`npm test || true` 这种把结果盖住的写法不算数，agent 会被要求单独重跑。
- **三轮不过就找你**：同一类检查连续失败 3 轮，agent 会停下来，不再改任何东西，把试过什么、失败输出、需要你决定什么交给你。Pitch agent 的自检（数字来源、长度、版式）也按这条算。
- **检查规则放在改动碰不到的地方**：改已有的测试文件，或者写 `REVIEW.md`、`AGENTS.md`、`CLAUDE.md`、`verification/`、`.claude/` 里的规则，每次都要你单独同意，“本次对话都允许”对它们不生效。新增测试不受影响。
- **关卡分三档**（设置 → 验收关卡）：`先观察`是默认，只记下哪些任务本该被拦；`严格`会把没验证的改动退回去先验证，最多退 2 次，之后放行并标为未验证；`关闭`则不盖章也不停。每次任务的章都记在 `data/verification.jsonl`，设置页有最近的统计。

已知局限：用 shell 命令改文件（`sed -i`、重定向等）是按常见写法识别的，不保证都能认出；一条命令算不算检查，是按命令名判断的。

## 可选增强

- **幻灯片版式检查**：`npm install playwright && npx playwright install chromium` 之后，每次生成 pitch 会在真实浏览器里检查有没有内容溢出，并让 agent 自己修。
- **更稳定的搜索**：用 Claude 时搜索由 Anthropic 的服务端工具完成；其他厂商默认用 DuckDuckGo，在设置里填 Brave Search key 更稳定。

## 现在还没有的

- 邮件、日历、Telegram 等外部账号接入，以及定时自动运行。
- 编程 agent 的命令没有容器隔离：文件工具出不了工作目录，但你批准的 shell 命令能做你的账号能做的任何事，批准前请看清楚。
- 独立评审：让另一个模型按评分表检查结果。上面那篇文章里，这一步把一类任务的成功率提高了最多 10 个百分点，越难的任务提升越大。
- 用真实模型打分的评测集。目前的自动测试（`npm test`）覆盖循环、权限、工具和两种模型接口的收发格式，用的是本地替身服务。

## 目录

```
server.js            本机服务与接口
src/loop.js          agent 循环：调用模型 → 执行工具（需要时先审批）→ 继续
src/agents.js        四个 agent 的角色说明与工具清单
src/llm/             模型适配：Claude、OpenAI 兼容（OpenAI / Grok / Kimi）、测试用替身
src/tools/           文件、命令行、联网、记忆、pitch、销售
src/deck.js          pitch 渲染与数字核对
src/verify.js        验收：记录改动与检查、盖章、三轮规则、关卡
public/              网页界面
test/                自动测试
```

加一个新 agent：在 `src/agents.js` 里加一项（角色说明 + 工具清单）。加一个新工具：导出 `{ name, description, schema, tier, run }`，`tier` 为 `auto`（直接执行）、`edit`（改文件，需确认）或 `exec`（运行命令，需确认）。
