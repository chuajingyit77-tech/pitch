# 备份：一条命令，结果用人话告诉他

## 备份

```
python3 tools/wos.py backup
```

它会：查仓库是公开还是私有 → 重新生成视图 → 过隐私闸门 → 提交 → 推送当前分支（失败自动重试）→ 核对 GitHub 上确实有这次提交。如果你的会话要求提交说明带署名行，用 `--trailer "第一行\n第二行"` 传进去。

读它的输出，用两到四行告诉老板：

- 备份到了哪个分支、几个文件；
- 有没有**没备份的私密文件**（仓库公开时会有）；
- 改动进没进 `main`。

返回码 3 表示没推上去：马上再运行一次；还不行就直说「改动只在这个会话里，还没送到 GitHub」，不要说成功。

## 隐私闸门关着的时候

每个会话说清楚一次，之后不重复：

> 这个仓库是公开的，任何人都看得到。标为内部和机密的资料我没有提交，它们只在这次会话里。
> 办法有两个：
> 1. 把这个仓库改成私有：GitHub 打开仓库 → Settings → 拉到最下面 Danger Zone → Change visibility → Private。
> 2. 另建一个私有仓库专门放工作系统，我把整套搬过去。

- 他改成私有后：`python3 tools/wos.py privacy --fresh` 确认，再 `backup`，之前被拦下的文件会一起提交。
- 接口查不到状态、但会话里的工具能确认仓库是私有的：把 `config/wos.json` 的 `visibility_override` 设成 `"private"`。
- 只有他明确说「公开我也要存」，才把 `allow_private_in_public_repo` 设成 true，并在提交说明里写上他的原话。

## 进 main（新会话才看得到）

新会话默认从 `main` 开始。只推到会话分支的改动，下次是看不到的。

- `config/wos.json` 里 `auto_merge_to_main` 是 true（老板授权过），或他当场说「合并到 main」：用 GitHub 工具从当前分支向 `main` 开一个合并请求，标题 `backup: <日期>`，用**合并提交**（不要压缩合并）合进去，然后告诉他。
- 没有授权：不要自己开合并请求。在备份结果里提醒一句「还没进 main」，问他要不要合并，或要不要以后每次备份都自动合并。

## 同步（把滞留在别的会话分支上的资料并进来）

开工状态里提示有未合并的分支，或他说「同步」时：

```
python3 tools/wos.py sync
```

它列出每个有新资料的分支和合并命令。逐个执行 `git merge --no-edit <提交号>`。有冲突时：

- 卡片正文里带日期的行：两边都留。
- 卡片表头同一个键两边不同：取 `touched` 更新的那边；拿不准就问他。
- 碎碎念文件：永远两边都留，不丢任何一条原话。

合并完运行 `check`、`build`、`backup`，告诉他并进来了什么。

## 系统体检

```
python3 tools/wos.py doctor
```

逐项通过／不通过。把结果用一句话告诉他，再列出不通过的项和你打算怎么修。

## 额外一份到 Google Drive（只在他要求时）

把 `项目 关系 碎碎念 水准` 和 `建议记录.md 想法停车场.md` 打成 zip，放到临时目录，用 Drive 工具传到「工作系统备份」文件夹，文件名 `worksystem-YYYYMMDD-HHMM.zip`。传完告诉他文件名。
