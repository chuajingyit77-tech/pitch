# 生成资料：底稿 → 事实表 → 初稿 → 自检 → 交付

## 0. 先读

1. `水准/我的水准.md`（全部规则）
2. 这个项目的 `卡片.md` 和 `底稿.md`（特别是「长期要求」）
3. `水准/资料骨架.md` 里这个子类对应的资料包
4. 这个项目相关的碎碎念原话（`碎碎念/`）和 `来料`（他给的文件）

## 1. 底稿（这个项目唯一的故事来源）

`项目/<项目>/底稿.md`，内部文件，章节固定：

> 一句话 ▸ 规格 ▸ 对方是谁、要什么、给不了什么 ▸ 主张与那个例子 ▸ 要对方做的那一步 ▸ 钱从哪里来 ▸ 做什么、不做什么 ▸ 红线与合规 ▸ 过关标准与停手线 ▸ 视觉方向 ▸ 长期要求 ▸ 变更记录

- 「规格」是一组 `项：值`：类型／子类／为谁做／读者／场合／语言／设备／截止。
- 「钱从哪里来」是他的四个字段：谁付款／预算来源／下一个收钱动作／Gate 日期。
- 「红线与合规」下面有小标题「不外露词」，一行一个，对外资料里不能出现。
- 「长期要求」：他说过一次的要求、这个项目的读者和设备、不要出现的词、不要做的事。
- **任何资料里的主张、要求、价钱、红线，底稿里没有的不能写。要改先改底稿。**

## 2. 事实表

`项目/<项目>/事实表.md`：

| 编号 | 说法 | 数值 | 性质 | 等级 | 来源 | 核实日期 | 可对外 |
|---|---|---|---|---|---|---|---|

- 性质：事实／假设。等级：V 有合同、付款、官方批准或实测；S 有可靠书面支持；C 对方口头声称；M 缺失、冲突或过期。
- 资料里出现的**每一个数字**都要在表里。表里没有的数字，不写；必须写时标「待确认」并进下面的清单。
- 「可对外」只有 V 和 S 才能填「是」。C 级数字不进客户提案、定价或成本模型。
- 表后面跟一节 `## 待确认`，分三组：要你确认的／要问对方的／要查资料的。

## 3. 初稿

按资料骨架里标「即时」的文件出初稿，章节标题照骨架原样用。

- 内部资料放 `内部/`，标题下第一行写 `> 内部用，不外发`，结尾有「待确认（本文用到的）」；计划类还要有「下一步」：今天／本周／过关标准。
- 对外资料放 `对外/`，用读者的语言（底稿 › 规格 › 语言），只用 V、S 级事实和明确标了「示意」的数字，不出现「待确认」、占位符和内部用语。某个主张缺 V/S 级事实撑着，就不写这个主张，在交付里列为缺口。
- 标「按需」的（网页、演示稿、报价单、精排的一页纸）不主动做，在交付里列成编号的选项让他点。
- 标「条件」的，条件成立才做（例如有会面日期才出作战手册）。

## 4. 自检（最多三轮，三轮不过就停）

先让工具查能机械查出来的（内部资料有没有标「内部用，不外发」、对外资料里有没有「待确认」和不外露词、数字在不在事实表里）：

```
python3 tools/wos.py doccheck "项目名"
```

「不过关」的必须修；「留意」的逐条处理（补进事实表，或在那一行标成待确认）。然后逐条过下面这些，没过就改，改完再过：

1. 第一句是不是结论？有没有正面回答他原话里问的那句？
2. 每个数字都在事实表里吗？对外资料里有没有 C、M 级的东西？
3. 内外分开了吗？在 `对外/` 里搜一遍「不外露词」、内部用语、别家客户的名字。
4. 结尾是不是行动：动词＋对象＋产出，有负责人、日期、过关标准？
5. 长度在骨架给的限内吗？有没有凑字数的空话、模板感的句子？
6. 语言对吗？对外文件名是不是英文？
7. 这类资料特有的完成标准过了吗？（`水准/我的水准.md` 第九节）
8. 这个项目的「长期要求」每一条都满足吗？

重要的对外资料，或他说「精修」时：另起一个全新的审稿子代理，只给它这份资料、`水准/我的水准.md` 和底稿，让它专门找违反的地方，再按它找到的改。

三轮还不过：停下，把试过什么、卡在哪、要他决定什么交给他。不要把半成品说成成品。

## 5. 要给人看的成品（网页、演示稿、精排一页纸）

只在他点了头之后做（先给大纲）。

- 动手前用一两句话定下视觉方向，贴着这个项目，不用模板。
- 单个 HTML 文件，打开就能用；手机 390 宽不横向滚动；深浅两种主题；不用 emoji 当图标；演示稿每页一个观点、标题是一句结论。
- **交付前亲眼看**：用 Playwright 截 390×844 和 1440×900 两张图，自己看过再交。没条件截图，就在交付里写「未验证」。
- 给他手机看的，用 Artifact 发成私人页面；链接单独一行。

## 6. 交付说明（固定格式）

```
结论：<一句话>

出了这些：
1. 《资料名》— 用处一句话
   项目/<项目>/内部/….md
   手机：能直接看
2. …

还不确定的（标了待确认）：…
要你定的：1. …  2. …
可以接着做的：A. 演示稿  B. 报价单  …（回个字母就做）
检查：自检 N 轮；看过截图／未验证（原因）
```

## 7. 收尾

更新卡片（他确认了回放和底稿 → `stage` 从 摸底 改 制作；写好 `next`、`next_due`、`next_test`、`touched`），然后 `python3 tools/wos.py build` 和 `backup`。

## 他不满意时

1. 当场在 `水准/反馈记录.md` 记一条：日期｜项目｜资料｜他的原话｜我理解的要求｜范围（这份资料／这个项目／所有项目）。
2. 写进这个项目底稿的「长期要求」，马上按它重做。
3. 同类不满第二次出现，或他说「以后都这样」：提议写进 `水准/我的水准.md`，他点头才写，并把那条规则的状态改成「已确认」。
4. 他确认满意的成品，在 `水准/我的水准.md` 第十节「范例」里记一行（路径＋好在哪里），以后同类资料先看范例。
