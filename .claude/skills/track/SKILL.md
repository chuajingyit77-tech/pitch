# 跟进表、提示、建议

提示是**规则算出来的**（脚本，每次结果一样）；建议是**你的判断**（要有依据，要记录下场）。两样不要混。

## A. 「跟进表」「今天该做什么」

```
python3 tools/wos.py build
```

读 `视图/今日.md` 和 `视图/跟进表.md`，然后回复：

1. 结论：今天最该做的一件事，一句话。
2. 「急」的全部列出；「注意」最多 5 条；「提醒」只报条数。每条：哪个项目或谁 → 什么事 → 建议的动作。
3. 看板链接单独一行（`config/wos.json` 的 `dashboard_url`；没有就按 B 发一个）。

他要全表才贴全表。三个级别的意思：

| 级别 | 只给这些事 |
|---|---|
| 急 | 他答应别人的事到期或过期；不能改的期限 3 天内或已过；止损线到检查日 |
| 注意 | 下一步过期或今天到期；没有下一步；Gate 临近或已过；对方欠的事过期；无付款路径；期限两周内 |
| 提醒 | 久没动静；该联系的人；搁置到了回看日；P1 太多；历史项目待确认 |

## B. 「刷新看板」

1. `python3 tools/wos.py build`，生成 `视图/看板.html`。
2. 用 Artifact 工具发布它：`config/wos.json` 里有 `dashboard_url` 就更新那一个（链接不变）；没有就新发一个私人页面，把链接写进 `dashboard_url`，再 `backup`。
3. 告诉他：这是什么、链接单独一行、手机能开、只有他自己看得到。

每次备份之后如果卡片有变化，顺手刷新看板。

## C. 改状态

改卡片表头，并在 `## 进展` 写一行 `- <日期> 阶段 旧→新`，更新 `stage_since` 和 `touched`。

- 搁置：必须有 `revisit`（回看日）。没给就问一句「哪天回头看？」。
- 终止：在 `## 决定` 写一句理由。
- 落地：给客户或市场做的，`evidence` 要是 V（合同、付款或批准）。不是就直说「落地要有 V 级证据，现在是 C」，按他的决定办。
- 完成：`## 承诺` `## 期限` 里没有还开着的行；有就列给他。
- 优先级 P1／P2／P3 只有他能定。你可以建议，不能自己改。

## D. 建议

每天短的（最多 3 条）或每周全的（最多 5 条＋每周六问）。先读：提示、所有进行中的卡片（目标、下一步、Gate、付款路径、止损线）、`水准/我的水准.md` 第七节、`建议记录.md`。

每条建议的格式：

```
建议：<一句话结论>
依据：<引用卡片里的事实，不用形容词>
下一步：<动词＋对象＋产出>，<日期>，过关标准：<…>
```

- 否决过的不再提；待定超过 7 天的，用一行问他：采纳、搁置，还是否决。
- 每条建议在 `建议记录.md` 加一行：`| 日期 | 项目 | 建议 | 待定 |`，他表态后改最后一栏。
- 没有依据就不提。宁可只给一条。

**每周六问**（他自己的问题，周回顾时逐条回答，答不出的写「卡片里没有这个数据」）：

1. 本周实际收到多少钱？
2. 未来 30 天最可能收到的三笔钱是什么？证据是什么？
3. 哪些项目没有付款人或预算，应该暂停？
4. 哪一项支出会令现金防线下降？是否值得？
5. 每名员工交出了什么可验收成果？
6. 哪些决定必须由我在 48 小时内作出？

## E. 「历史项目过一遍」

`stage: 待确认` 的是从旧分支导入的。每次问 5 个，每个只要他回一个词：还在做／已结束／搁置／不做了。按回答改 `stage`（还在做的补上 `next` 和日期），然后 `check`、`build`、`backup`。

## F. 每周自动回顾

可以设一个定时任务，每周固定时间开一个新会话跑一遍 A 和 D，并发通知到他手机。**只提议，他说好才建。**
