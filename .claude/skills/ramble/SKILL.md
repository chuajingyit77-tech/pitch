# 碎碎念：先存原话，再拆，再回放，再落卡

老板的原话是这套系统唯一的输入。顺序不能乱：**存 → 拆 → 回放 → 问 → 落卡 → 做资料 → 备份。**

## 1. 存（逐字，不整理）

```
python3 tools/wos.py ramble list                 # 看这个会话截到的原话，1 是最新一条
python3 tools/wos.py ramble save --pick 1 --title "短标题" --sens 内部
```

- 一段话分了几条消息发：`--pick 3,2,1`，会按先后拼成一个文件。
- 文件存到 `碎碎念/<年-月>/`，带校验码。**存好之后不再改动它**；后来的补充是新的一条碎碎念。
- 收件箱是空的（钩子没生效）时，自己新建文件，把他的话原样贴进去：不改错字、不删口头语、不调顺序。
- 只有内容本来就不敏感时才用 `--sens 公开`。
- 存完马上运行一次 `python3 tools/wos.py backup`。仓库公开时它会告诉你这条原话没法备份——用一句话告诉老板（见 CLAUDE.md 第六节）。

## 2. 拆（一段话里常有好几件事）

| 他讲的是 | 去哪里 |
|---|---|
| 一个新项目 | `python3 tools/wos.py new project --name "…" --type … --subtype … --for-whom …`，再写底稿（`make-docs`） |
| 已有项目的进展 | 那张卡片：`## 进展` 加一行；更新 `next`、`next_due`、`next_test`、`stage`、`touched` |
| 见了谁、谁说了什么 | 关系卡片 `## 往来`（`people` 技能） |
| 谁答应了什么 | 项目或关系卡片的 `## 承诺`：`我答应` ／ `对方答应`，带日期 |
| 一个不能动的日期 | `## 期限` |
| 他拍板的一件事 | `## 决定` |
| 还不算项目的想法 | `想法停车场.md` 加一行（日期＋一句话） |
| 对成品的不满、「我说过…」 | `水准/反馈记录.md` 记一条；写进这个项目底稿的「长期要求」，立刻生效 |
| 一句指令（备份、跟进表…） | 对应的技能 |

先找已有的：在 `项目/`、`关系/` 里按名字和 `aliases` 搜。他说「银行那个案子」，就把这个说法加进那张卡的 `aliases`。

## 3. 回放（让他一眼看出你听懂没有）

```
我听到的是：<一句话，不超过 60 字>

事实（你说的）
- …
假设（我推断的，错了你纠正）
- …
缺口（还不知道的）
- …

我打算
1. 建／改哪张卡片
2. 出哪几份资料（按 水准/资料骨架.md 里这个子类的资料包）
```

分类时说明理由（例如「主要产出是为了赢下一个客户，所以归 其他 · 提案」）。

## 4. 问（少而准）

- 每轮最多 3 问，最多 2 轮。只问答案会改变成品的：**给谁看、要对方做哪一步、什么场合和日期、钱从哪里来**。
- 问之前先查：卡片、底稿、`水准/`、以前的碎碎念里有的，不问第二遍。
- 他说「先这样」「你看着办」：按默认做，把默认写进「假设」，交付时列出来。
- 缺口不要用猜的补上。缺的写 `待确认`。

## 5. 落卡

按 CLAUDE.md 第五节的写法改卡片，然后：

```
python3 tools/wos.py check
```

底稿的「变更记录」加一行：日期、这次碎碎念改了什么。旧的碎碎念文件永远不动。

## 6. 做资料

新项目，或者这次碎碎念改变了主张、对象、要对方做的那一步、价钱 → 进入 `make-docs`。只是进展更新就不用重做资料，但要检查已有资料有没有因此过时，过时的在交付里点出来。

## 7. 收尾

```
python3 tools/wos.py build
python3 tools/wos.py backup
```

回复老板（结论先说）：我建了／改了什么 → 出了哪些资料（编号，各一句用处，路径单独一行）→ 还不确定的 → 要你定的 → 备份结果。
