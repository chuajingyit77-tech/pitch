# 四个 AI Agent 的构建计划

> **更新：** `agent-hub/` 里已经有一个把四个 agent 合在一起、可以直接运行的系统，名叫“掌柜”。要让 Grok、Kimi、Codex 一起继续改进，请把 `05-extend-zhanggui.md` 粘贴给它们——比按下面四份计划各自从零开始更快，也不会做出四套互不相通的东西。下面的 01–04 保留作参考。

每个文件都是一份可以整段复制、直接粘贴给构建方的完整指令，互不依赖，可以同时开工。

| # | Agent | 计划文件 | 建议谁来做 | 运行时用哪家模型 | 运行形态 |
|---|-------|---------|-----------|----------------|---------|
| 1 | Pitch 生成 | `01-pitch-agent.md` | Claude Code（本仓库） | Claude（长文写作 + 前端视觉生成） | 网页应用 |
| 2 | 通用个人助理 | `02-assistant-agent.md` | Kimi | Kimi（长上下文、中文、长文档阅读） | 网页 + Telegram + 定时任务 |
| 3 | 销售/获客 | `03-sales-agent.md` | Grok | Grok（实时网页与 X 搜索） | 后台定时运行 + 审批面板 |
| 4 | 编程 | `04-coding-agent.md` | Codex | OpenAI 的编程模型 | 命令行工具 |

分工是我的判断，不是硬性规定：每份计划都要求把模型调用放在一层薄适配器后面，之后想换厂商只改配置。

## 协作规则（四方同时进行时）

- 每个 agent 只在自己的目录里工作：`agents/pitch/`、`agents/assistant/`、`agents/sales/`、`agents/coding/`，不要改别人的目录。
- 每个 agent 用自己的分支，做完再合并。
- 密钥只放 `.env`，仓库里只提交 `.env.example`。

## "最强"怎么衡量

模型只是一部分。真正拉开差距的是：工具设计、自我检查循环、以及一套能打分的评测集。四份计划都把评测集列为必须交付物——没有评测分数，就没法说哪个更强，也没法知道改动是变好还是变差。
